<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Docker build → github.com/rui314/mold | Untrusted upstream tarball downloaded and extracted into /usr/local |
| Docker build → rpm.nodesource.com | Third-party vendor Node 24 rpm installed into the image |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Spoofing | mold tarball download URL | mitigate | `wget -q` over HTTPS to the official `github.com/rui314/mold/releases` tag `v2.42.0` |
| T-02-02 | Tampering | mold tarball contents | accept | GitHub TLS + release provenance only; the analog does not SHA256-pin mold (parity — hardening is a deferred user decision) |
| T-02-03 | Tampering | NodeSource `nodejs` rpm | mitigate | repo installed in Phase 1 with `gpgcheck=1`; first-party vendor repo; `node -e 'process.exit(0)'` probe catches a non-EL8 (wrong-glibc) binary |
| T-02-04 | Elevation of privilege | `update-alternatives` ld shim | accept | Registers mold as default `ld` with priority 100 — same trust posture as the bullseye analog; revert documented in the block comment |
| T-02-SC | Tampering | npm/pip/cargo installs | accept | No npm/PyPI/crates packages — all artifacts are upstream tarballs or official vendor RPMs (Package Legitimacy Audit clean; slopcheck not applicable) |
</threat_model>
