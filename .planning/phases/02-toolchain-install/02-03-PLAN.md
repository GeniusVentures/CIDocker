<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Docker build → final image | ENV contract and runtime-glue config are baked into the image consumed by CI |
| CI build (at runtime) → git repositories | `safe.directory '*'` widens git's trusted-directory scope for the container |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-09 | Information disclosure | seeded machine-id (`/etc/machine-id`) | accept | Value is a random UUID from the kernel (`/proc/sys/kernel/random/uuid`), not a host identifier; identical-to-bullseye parity |
| T-02-10 | Elevation of privilege | `git config --system --add safe.directory '*'` | accept | Intentional parity with bullseye so CI can operate on any mounted repo; container-scoped, no host trust |
| T-02-11 | Tampering | env-contract integrity | mitigate | Verification chain echoes and asserts `JAVA_HOME`/`JDK_HOME`/`RUSTUP_HOME`/`CARGO_HOME` at build time |
| T-02-SC | Tampering | npm/pip/cargo installs | accept | No npm/PyPI/crates packages — upstream tarballs + official vendor RPMs only (Package Legitimacy Audit clean; slopcheck not applicable) |
</threat_model>
